# D1: Ordered join in an order statistic AVL tree

**Author:** Chaitanya Sharma  
**Structure:** AVL tree ordered by score descending, then player ID ascending

## Goal and precondition

Combine two AVL trees `L` and `R` around a pivot entry `p`. The operation is valid only if every key in `L` precedes `p` and `p` precedes every key in `R`. This strict boundary condition is what makes the result a binary search tree. The implementation checks the maximum key of `L` and minimum key of `R` before transferring ownership.

## Height cases

If the heights are close, the pivot can be the root immediately:

```text
Compatible heights: height(L), height(R) differ by at most one
        p
       / \
      L   R
```

For a much taller left tree, descend its right spine until a subtree can be joined with the pivot and the right tree:

```text
Tall-left case: follow the right spine
    L
     \
      B
       \
        X  <- join(X, p, R)
```

The mirrored case follows the taller right tree's left spine. After joining at the boundary, repair balance on the path back to the root. Each ancestor keeps its other subtree unchanged.

```text
Local repair: one right rotation
      z                 y
     / \               / \
    y   C     ->      A   z
   / \                   / \
  A   B                 B   C
```

If `y` leans right, a left-then-right double rotation is needed. The symmetric pair handles right-heavy ancestors.

## Correctness argument

**Ordering.** In the compatible-height case, the input precondition places every key of `L` below `p` in the tree order and every key of `R` above `p`. In the tall-left case, all keys in the untouched left subtrees remain before `p`; the recursively joined subtree contains the suffix of `L` and `p` followed by `R`, preserving the same order. The symmetric argument applies to a tall-right tree. Rotations preserve in-order traversal, so they preserve this ordering.

**AVL balance.** When subtree heights differ by at most one, the new pivot has a balance factor in `[-1,1]`. Otherwise, recursion descends one level along the taller tree's inner spine. At the stopping point, it creates a locally balanced pivot node. Each ancestor changes only through its inner child; a single or double AVL rotation restores a balance factor in `[-1,1]`. The recursive routine returns a valid AVL subtree, so this repair proceeds inductively to the root.

For a left-heavy ancestor, a left-heavy (or level) left child is repaired with one right rotation. If the left child leans right, first rotate that child left, then rotate the ancestor right; the middle subtree becomes the pivot between the two outer subtrees. The right-heavy cases mirror these steps. Rotations preserve the in-order sequence while moving the taller side's root toward the center; the two resulting child heights differ by at most one. This is why balance is restored without changing key order.

**Metadata.** `fix(node)` computes `height = 1 + max(height(left), height(right))` and `count = 1 + count(left) + count(right)`. It runs after child links are set and after each rotation, bottom-up. Therefore every returned node has correct height and subtree size. These sizes support logarithmic selection and rank queries.

**Ownership.** The public `join` takes rvalue references. After validating the boundary, it exchanges each input root with null; the result becomes the sole owner of all transferred nodes and the newly allocated pivot node. Recursive `join_nodes` rearranges links among those nodes without copying or sharing nodes. Destruction of the moved-from inputs is safe because their roots are null. If precondition validation fails, it happens before either root is exchanged, leaving both trees intact.

## Complexity

Assume `hL >= hR`. The internal join follows the right spine of `L` until the current subtree height is at most `hR + 1`. Each recursive step moves down one level, and the amount of descent is at most `hL - hR + 1`; the symmetric case is identical. Every visited level performs constant-time metadata repair and at most two rotations. Internal `join_nodes` therefore takes `O(|hL-hR|+1)` time. The public `join` first searches one boundary spine in each input tree to validate ordering, which costs `O(hL+hR)`. Its overall time is `O(log n)` for AVL inputs.

For a range query that returns `k` players, the implementation must append and materialize `k` entries in its output vector. That requires at least `O(k)` time regardless of tree balance; the pruned traversal adds only the search paths around the range.
