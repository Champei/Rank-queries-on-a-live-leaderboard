# D2: Correctness of Fenwick binary lifting

**Author:** Teerth Dudhagara (250001027), Structure B

**Project statement (D2):** The binary-lifting descent returns the smallest index whose prefix count is at least k, in O(log U). Prove it.

**Used in:** src/structB/fenwick.cpp, Fenwick::select_score. Source consulted: P. M. Fenwick, *A new data structure for cumulative frequency tables* (1994).

## Definitions and target

The Fenwick tree has U sorted, unique score coordinates. cnt[i] is the nonnegative player count at zero-based coordinate i; bit[j] uses one-based Fenwick indexing. Define P(j) = cnt[0] + ... + cnt[j-1] and P(0) = 0. Then P is nondecreasing and P(U) = total. For one-based position in descending score order, select_score rejects positions outside [1,total] and converts to the ascending target k = total - position + 1. The desired answer is the smallest one-based coordinate j with P(j) >= k, returned as scores[j-1].

## Loop invariant

Let b be the largest prefix length with P(b) < k. It exists because k >= 1, and b < U because P(U) >= k. The code starts at at = 0, target = k, and tests powers step = S, S/2, ..., 1, where S is the largest power of two at most U. Before a test, maintain:

1. P(at) < k and target = k - P(at).
2. at is a multiple of 2*step.
3. at <= b < at + 2*step.

Initially these hold: at = 0, and 0 <= b < U < 2*S. For candidate next = at + step, the alignment condition makes step the lowest set bit of next. Thus bit[next] stores precisely the block after the skipped prefix: bit[next] = P(next) - P(at). So bit[next] < target is equivalent to P(next) < k.

If next <= U and that comparison is true, the code skips this block, sets at = next, and subtracts bit[next] from target. Then at <= b and the old upper bound gives b < at + step. Otherwise next > U or P(next) >= k, so b < next = at + step and the code keeps at. In both cases at <= b < at + step; halving step establishes the same invariant for the next test, including the alignment.

After step = 1, integers at <= b < at + 1 force at = b. Hence P(at) < k <= P(at+1), so at+1 is the *smallest* one-based coordinate reaching k, and scores[at] is correct. The comparison must be strict: skipping a block whose sum reaches k would skip the answer. Zero-count coordinates can make consecutive prefixes equal, but they do not violate monotonicity or the proof.

## Example and cost

For scores [10,20,30,40,50] with counts [2,0,1,3,0], the prefixes are [0,2,2,3,6,6]. Selecting descending position 3 gives k = 6-3+1 = 4. At steps 4, 2, 1, the algorithm keeps at=0 (bit[4]=6), advances to at=2 (bit[2]=2), then to at=3 (bit[3]=1). It returns score 40 because P(3)=3 < 4 <= P(4)=6. For k=2, the strict comparison prevents skipping bit[2]=2, returning score 10.

Finding S and testing its powers each take O(log U) iterations with constant work per step, so the descent takes O(log U) time and O(1) extra space. The fixed coordinate universe is required: inserting an unseen score shifts indices and needs a rebuild, as implemented by Fenwick::rebuild.
