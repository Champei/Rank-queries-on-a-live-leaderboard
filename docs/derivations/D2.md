# D2: Fenwick binary-lifting descent

Author: Teerth Dudhagara (250001027) - Structure B

## Assigned statement

“The binary-lifting descent returns the smallest index whose prefix count is at least k, in O(log U). Prove it.”

## Definitions and connection to the code

There are U sorted, unique allowed scores. Let c[i] be the player count at one-based coordinate i, and P(j) be the sum of c[1] through c[j], with P(0)=0. Counts are nonnegative, so P is nondecreasing. For 1 <= k <= total, the required answer is the smallest coordinate j with P(j) >= k.

The implementation is `Fenwick::select_score` in `src/structB/fenwick.cpp`. Its `scores` array is zero-based, while `bit` is one-based. A descending position p is converted to the ascending target k=total-p+1. Invalid positions are rejected before searching. During the search, `at` counts skipped coordinates and `target` is the remaining count needed.

## Loop invariant

Let b be the largest prefix length with P(b)<k. It exists since P(0)=0<k, and b<U since P(U)=total>=k. Before testing a power s, maintain:

1. P(at)<k and target=k-P(at).
2. at is a multiple of 2s.
3. at <= b < at+2s.

Initially at=0 and target=k. The first power S satisfies S<=U<2S, so all three statements hold. A valid position implies U>=1.

## Preservation and termination

The candidate is next=at+s. By the alignment invariant, the lowest set bit of next is s. If next<=U, its Fenwick entry therefore covers precisely the coordinates at+1 through next:

`bit[next] = P(next)-P(at)`.

Thus `bit[next] < target` is equivalent to P(next)<k.

If the test succeeds, next<=b. Set at=next and subtract the skipped block from target, preserving target=k-P(at). The previous interval gives b<new_at+s. If it fails, either next>U or P(next)>=k; in either case b<next=at+s, so keep at and target. Hence after either outcome, at<=b<at+s.

When s is halved, this is the next interval invariant. The new at is a multiple of the old s, which is twice the next power, so alignment also holds. After s=1, at<=b<at+1; since both are integers, at=b. Consequently P(at)<k<=P(at+1). The smallest one-based answer is at+1, corresponding to zero-based `scores[at]`, exactly what the function returns.

The comparison is strict: equality means the candidate prefix already reaches k, so the answer must not be skipped.

## Worked example, including zero counts

Universe [50,10,30,10,40,20] compresses to [10,20,30,40,50]. Insert scores [10,30,40,40,10,40], giving total=6:

| Coordinate | Score | Count | Prefix P | bit |
|---|---:|---:|---:|---:|
| 1 | 10 | 2 | 2 | 2 |
| 2 | 20 | 0 | 2 | 2 |
| 3 | 30 | 1 | 3 | 1 |
| 4 | 40 | 3 | 6 | 6 |
| 5 | 50 | 0 | 6 | 0 |

For descending position p=3, k=6-3+1=4. Start at=0, target=4:

| Power s | next | Decision | State afterwards |
|---|---:|---|---|
| 4 | 4 | bit[4]=6 is not <4: keep | at=0, target=4 |
| 2 | 2 | bit[2]=2 is <4: skip | at=2, target=2 |
| 1 | 3 | bit[3]=1 is <2: skip | at=3, target=1 |

Return scores[3]=40. Indeed P(3)=3<4<=P(4)=6. Empty score 20 is safely included in the skipped prefix. Zero counts allow equal adjacent prefix sums but preserve monotonicity. For p=5, k=2: equality at bit[2]=2 must not be skipped, and the answer is 10.

## Complexity and fixed universe

Finding LOG takes O(log U) time. The descent tests floor(log2 U)+1 powers, with constant work each, so total time is O(log U) and extra space is O(1). It reads bit entries directly; calling prefix at every candidate would instead introduce another logarithmic factor. For U=1 there is one test.

Every score that may be inserted must have an allowed coordinate beforehand. In this example 35 is absent, so accepts(35) is false and update(35,1) is rejected. Adding a coordinate between 30 and 40 changes later indices and Fenwick block boundaries; rebuild with the expanded universe and current player scores. Empty but allowed coordinates remain valid. The numeric replay prepares scores 0 through 10000 before updates.
