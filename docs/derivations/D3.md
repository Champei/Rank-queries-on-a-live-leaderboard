# D3: Competition rank in both structures

For a player with score `s`, partition all players into scores greater than `s`, equal to `s`, and less than `s`. Let `H(s)` be the number in the first group. Competition ranking assigns the player rank `1 + H(s)`. Equal-score players have the same rank because `H(s)` depends only on the score. For descending scores `90, 80, 80, 70`, the ranks are `1, 2, 2, 4`.

The AVL orders entries by descending score and then ascending player ID. Every entry with score greater than `s` precedes every entry with score `s`. The AVL's subtree sizes let `rank(s)` count exactly those preceding, strictly higher-score entries, so it returns `1 + H(s)`. It must skip the entire equal-score group; the ID tie break is only for `select(position)` and `rank_range`.

The Fenwick tree stores the number of players at each score. Let `N` be its total count and let `P(s)` be the prefix sum through the last compressed coordinate whose score is at most `s`. Then `P(s)` counts exactly the equal- and lower-score players. Therefore `N - P(s) = H(s)`, and `Fenwick::rank(s) = 1 + N - P(s) = 1 + H(s)`. This also works when `s` is between coordinates: the prefix still contains exactly the scores at most `s`.

Initially both structures are empty. `Leaderboard::revise` removes the old `(score, ID)` entry and one old score count, then inserts the new entry and count; `remove` deletes both. Thus after each completed operation both represent the same players. By the arguments above, their ranks agree for every stored player. A split or merge rebuilds the Fenwick counts and hash from the corresponding AVL entries or revisions, preserving the same invariant.

For example, players `(90, 7), (80, 2), (80, 9), (70, 4)` have competition ranks `1, 2, 2, 4`, while positions 2 and 3 contain IDs 2 and 9 respectively. The rank of player 9 is 2, although that player occupies position 3.
