# D5: Split and adversarial rotations

**Author:** Jay Gupta  
**Role:** Member 5, Adversary (`adversary/`)

**Notation.** Keys are `Entry{score, player_id}` pairs, ordered as in `INTERFACE.md`: higher score first, then lower ID. "Left" means earlier in this order, and "tree position `p`" means the `p`-th key in this order, counting from 0. `h(T)` is the height of tree `T`, with `h(empty) = 0` and `h(leaf) = 1`, as in `Avl::height`. The balance of a node is `h(left) - h(right)`. `rotations()` counts single rotations, so a double rotation counts as 2. `bitlen(n)` is the number of binary digits of `n`, which equals `⌊log2 n⌋ + 1 = ⌈log2(n+1)⌉`.

## Part 1. Sorted insertion forces a rotation on almost every insert

**Family.** `rotation_inserts(n)` inserts `(score i, id i)` for `i = 0, 1, …, n-1`. Each new score is higher than all earlier ones, so each new key becomes the new *first* key, and `insert` places it as the leftmost leaf. Let `T(k)` be the tree after `k` inserts.

**Theorem 1.** Insert number `k` performs exactly one single rotation if `k` is not a power of two, and no rotation if it is. So building `T(n)` performs exactly `n - bitlen(n)` rotations, and the fraction of inserts that rotate is `1 - bitlen(n)/n`. That fraction is at least `1/4` for every `n ≥ 4` and tends to 1.

**The first eight inserts.** Nodes are labelled by score; a higher score is further left. Inserts 1, 2, 4 and 8 (powers of two) make the tree taller with no rotation. Every other insert does one right rotation, at the node marked `*` before the rotation.

```text
#1  0          #2   0         #3     0*  ->  1        #4      1
                   /                /       / \              / \
                  1                1       2   0            2   0
                                  /                        /
                                 2                        3

#5      1            1        #6      1*        ->     3
       / \          / \              / \              / \
      2*  0   ->   3   0            3   0            4   1
     /            / \              / \              /   / \
    3            4   2            4   2            5   2   0
   /                             /
  4                             5

#7       3            3        #8         3
        / \          / \                 / \
       4*  1   ->   5   1               5   1
      /   / \      / \ / \             / \ / \
     5   2   0    6  4 2  0           6  4 2  0
    /                                /
   6                                7
```

`T(3)` and `T(7)` are perfect, so inserts 4 and 8 can only make the tree one level taller. This is Lemma 3 below.

The left spine of a tree is the path root, root.left, root.left.left, and so on. Every new key is inserted at the bottom of the left spine, so the insertion path is the left spine.

**Invariant I.** Every node on the left spine of `T(k)` has balance `≥ 0`.

**Invariant II.** For every node on the left spine of `T(k)`, its right subtree is a perfect binary tree.

**Lemma 1 (what one insert can do).** After the new leaf is attached, `balance` is applied to each ancestor from the bottom up. In an AVL insert exactly one of three things happens:
- **(a) absorbed:** some ancestor's height does not change, so nothing above it changes and no rotation happens;
- **(b) rotation:** some ancestor reaches balance `±2`, is rotated, and its subtree returns to its old height, so nothing above changes;
- **(c) height increase:** every ancestor grows by one, and the tree height increases by 1 with no rotation.

**Lemma 2.** If Invariants I and II hold for `T(k-1)`, then insert `k` is never case (a), and if it is case (b) the rotation is a single right rotation. Both invariants also hold for `T(k)`.

*Proof.* The new leaf has balance 0. Walk up the spine. Every spine node `v` that is reached has its left subtree grown by exactly one, so its balance rises by one. By Invariant I it was 0 or 1, so it becomes 1 or 2. It cannot become 0, so case (a) never happens.

- **Balance becomes 1.** It was 0, so `h(v)` grew, and the walk continues upward. `v` now has balance 1, so Invariant I still holds at `v`. Its right subtree is untouched, so Invariant II still holds.
- **Balance becomes 2.** Let `x = v`, `y = x.left` and `c = h(x.right)`. Before the insert `x` had balance 1, so `h(y) = c + 1`. `y` was reached earlier in the walk, and its balance became 1 rather than 2, since otherwise the rotation would have happened at `y`. So `y` had balance 0 before: `h(y.left) = h(y.right) = c`. Now `h(y.left) = c + 1 > h(y.right) = c`, so `Avl::balance` takes the single-rotation branch (`height(n->left->right) > height(n->left->left)` is false). After `rotate_right(x)`:
  - `x` has children `y.right` (height `c`) and the old `x.right` (height `c`). By Invariant II both are perfect, so `x`'s subtree is perfect with height `c + 1`.
  - `y` has children `y.left` (height `c + 1`) and `x` (height `c + 1`). So `y` has balance 0, and its height is `c + 2`, the same as `x`'s old height. The walk stops.

  `y` is now on the spine with balance 0 and a perfect right subtree. Spine nodes below `y` were handled by the first bullet. Spine nodes above `x` did not change. Both invariants hold. ∎

In the diagrams, insert #5 is this case with `x = 2`, `y = 3`, `c = 0`, and insert #6 with `x = 1`, `y = 3`, `c = 1`.

Both invariants hold for `T(1)`, a single leaf. By induction on `k` with Lemma 2, they hold for every `T(k)`, and every insert is case (b) with one single rotation, or case (c).

**Lemma 3.** If insert `k` is case (c), then `T(k-1)` is perfect, so `k` is a power of two.

*Proof.* In case (c) every spine node of `T(k-1)` had balance 0 (none reached 2). Go up the spine from the bottom. The lowest spine node has an empty left subtree, so with balance 0 its right subtree is also empty, and it is a perfect leaf. Each spine node higher up has a perfect left subtree (induction going up), a perfect right subtree (Invariant II), and balance 0, so it is perfect. So the root's tree `T(k-1)` is perfect, `k - 1 = 2^j - 1`, and `k = 2^j`. ∎

*Proof of Theorem 1.* Only case (c) changes the height, by +1 each time, starting from height 0. So the number of case-(c) inserts among the first `n` equals `h(T(n))`, and the number of rotations is `n - h(T(n))`.
- **Upper bound on the height.** By Lemma 3, every case-(c) insert is a power of two at most `n`, and there are `bitlen(n)` of those. So `h(T(n)) ≤ bitlen(n)`.
- **Lower bound on the height.** A binary tree of height `h` has at most `2^h - 1` nodes, so `h(T(n)) ≥ ⌈log2(n+1)⌉ = bitlen(n)`.

So `h(T(n)) = bitlen(n)` and there are exactly `n - bitlen(n)` rotations. Since the bounds are equal, every power of two is a case-(c) insert, and every other insert rotates once.

Constant fraction: `bitlen(n) ≤ log2 n + 1 ≤ 3n/4` for `n ≥ 4`. Equality holds at `n = 4`, and the right side grows faster after that. So at least `n/4` inserts rotate. ∎

## Part 2. A delete order that also rotates almost every time (measured, not proved)

**Family.** `rotation_deletes(n)` empties `T(n)`. With `r = n mod 4`, it first deletes tree positions `0, …, r-1`. Then, for `b = r, r+4, r+8, …`, it deletes positions `b+2, b, b+1, b+3`: the third, first, second and fourth key of each block of four. Positions refer to the original tree `T(n)`. The key at position `p` is `(score n-1-p, id n-1-p)`.

**How it was found.** `scratch/scratch-e/delete_search.cpp` keeps an array-based copy of `avl.cpp`'s insert, erase and rebalancing. The copy matches the real `Avl` rotation counter on 200 random insert/delete sequences. The search starts from `T(n)`, tries every possible next delete on a copy of the tree, and keeps the one with the most rotations. Counted among the keys still in the tree, its picks repeat "3rd, 1st, 1st, 1st". That is the block order above.

**Results on the real `Avl`** (`scratch/scratch-e/member5-test-results.txt`):

| n | greedy search | `rotation_deletes` | starter order (current last key) | `n - bitlen(n)` |
|---:|---:|---:|---:|---:|
| 63 | 56 | 56 | 26 | 57 |
| 100 | 93 | 93 | 44 | 93 |
| 255 | 246 | 246 | 120 | 247 |
| 500 | 491 | 491 | 242 | 491 |
| 10 000 | — | 9 986 | 4 988 | 9 986 |
| 1 000 000 | — | 999 980 | 499 981 | 999 980 |

For every `n` from 1 to 3000, `rotation_deletes` performs at least `n - bitlen(n) - 1` rotations. It reaches `n - bitlen(n)` or more at 2250 sizes, and is exactly one short at the other 750. That is about one rotation per delete, twice the starter order's 0.5. It also equals the greedy search at every size tested.

**What is not claimed.**
- I have no proof of this bound. The figures above are measurements on every size up to 3000 and on selected larger sizes.
- One AVL delete can rotate at every level of the tree, up to `O(log n)` rotations. The greedy search only looks one delete ahead. So about one rotation per delete is the best found, not a proven maximum.

## Part 3. Split costs O(log n)

**Join facts.**
- **Cost** (proved in D1): for the internal `join_nodes(L, k, R)`, at most `|h(L) - h(R)| + 1` recursive calls with constant work each.
- **Public `join` versus `join_nodes`.** The public `Avl::join` first checks the precondition by walking one spine of each input, which costs `O(h(L) + h(R))`. `split_node` calls `join_nodes` directly, so a split does not pay for this check.

**Lemma 4 (join height).** `h(join_nodes(L, k, R))` is `M` or `M + 1`, where `M = max(h(L), h(R))`.

*Proof.* Use induction on `|h(L) - h(R)|`.
- **Heights within 1.** The pivot becomes the root, and the height is `M + 1`.
- **`h(L) ≥ h(R) + 2`.** (The other side is symmetric.) Let `A = L.left` and `B = L.right`. Both have height `h(L)-1` or `h(L)-2`, and at least one has height `h(L)-1`. Since `h(B) ≥ h(L)-2 ≥ h(R)`, induction applies to `T' = join_nodes(B, k, R)`, and `h(T')` is `h(B)` or `h(B)+1`.
  - **`h(T') ≤ h(A) + 1`.** `L` needs no rotation, because `h(A) ≤ h(B) + 1 ≤ h(T') + 1`. Its height is `1 + max(h(A), h(T'))`, which lies between `1 + max(h(A), h(B)) = h(L)` and `h(L) + 1`.
  - **`h(T') = h(A) + 2`.** This is the only other possibility. It forces `h(A) = h(L)-2` and `h(T') = h(L)`. Write `a = h(A)`. `T'`'s children have heights `a` or `a+1`.
    - **Single rotation** (`T'.right` has height `a+1`): the new root has children `node(A, T'.left)`, with height `a+1` or `a+2`, and `T'.right`, with height `a+1`. So its height is `a+2` or `a+3`, which is `h(L)` or `h(L)+1`.
    - **Double rotation** (`T'.left` has height `a+1`): both new children have height `a+1`, and the root has height `a+2 = h(L)`.

In every case the height is `M` or `M + 1`. ∎

**Facts used about AVL trees.** In a node of height `σ`, each child has height `σ - 1` or `σ - 2`. An AVL tree with `n` nodes has height `H < 1.4405 log2(n + 2)`.

**How `split_node` works.** It follows one search path to the pivot (at most `H` nodes). At each node `u` on the path:
- If the pivot goes left, `u` and its untouched right subtree go to the **right side**: `join_nodes(middle, u, u.right)`, where `middle` is the right-side piece built from below.
- If the pivot goes right, `u` and its untouched left subtree go to the **left side** in the same way.
- A side's piece passes unchanged through nodes that feed the other side.

**Theorem 2.** The total work of all joins in one split is `O(H) = O(log n)`.

*Proof (right side; the left side is symmetric).* Let `u_1, …, u_m` be the path nodes that feed the right side, from the deepest up. Let `σ_j = h(subtree(u_j))` in the original tree, and `ρ_j = h(u_j.right)`, so `σ_j - 2 ≤ ρ_j ≤ σ_j - 1`. The subtrees are nested, so `σ_1 < σ_2 < … < σ_m ≤ H`, and `m ≤ H`.

Let `t_0` be the right part coming up from the bottom of the path: the found node's right child, or empty. Let `t_j = join_nodes(t_{j-1}, u_j, u_j.right)`. Every key of `t_{j-1}` lies in `u_j`'s left subtree.

*Step 1: `h(t_j) ≤ σ_j`.* `t_0` lies inside `u_1`'s left subtree, so `h(t_0) ≤ σ_1 - 1`. If `h(t_{j-1}) ≤ σ_{j-1} ≤ σ_j - 1`, then by Lemma 4 `h(t_j) ≤ max(h(t_{j-1}), ρ_j) + 1 ≤ σ_j`.

*Step 2: the cost of each join.* The cost of join `j` is at most `|h(t_{j-1}) - ρ_j| + 1`. There are two cases:
- If `h(t_{j-1}) ≤ ρ_j`, the cost is at most `ρ_j - h(t_{j-1}) + 1 ≤ σ_j - h(t_{j-1})`.
- If `h(t_{j-1}) > ρ_j ≥ σ_j - 2`, then by Step 1 `h(t_{j-1}) = σ_j - 1`, the difference is at most 1, and the cost is at most 2.

In both cases, `cost_j ≤ σ_j - h(t_{j-1}) + 1`.

*Step 3: the costs telescope.* For `j ≥ 2`, Lemma 4 says the join result is at least as tall as either input, so `h(t_{j-1}) ≥ ρ_{j-1} ≥ σ_{j-1} - 2`. Then `cost_j ≤ σ_j - σ_{j-1} + 3`. For `j = 1`, `cost_1 ≤ σ_1 + 1`. Summing:

`Σ cost_j ≤ (σ_1 + 1) + Σ_{j=2..m} (σ_j - σ_{j-1} + 3) = σ_m + 1 + 3(m - 1) ≤ 4H.`

The `σ` terms telescope. A naive bound of `O(log n)` per join would give `O(log² n)`. The left side gives another `≤ 4H`, and the descent costs `O(H)`. The total is `O(H) = O(log n)`. ∎

`split_score(t)` is `split({t, -1})`. ID `-1` is never stored, because `insert` and `join` reject negative IDs, so the sentinel sits exactly between scores `> t` and scores `≤ t`, and the same bound applies.

**Worked example.** Take a perfect tree on keys 1 to 15 (root 8, height 4) and split at 5. The search path is 8 → 4 → 6 → 5.

```text
                8                      path: 8 (go left)  -> 8 and subtree(12) go RIGHT
            /       \                        4 (go right) -> 4 and subtree(2)  go LEFT
           4         12                      6 (go left)  -> 6 and subtree(7)  go RIGHT
         /   \      /   \                    5 found; its children are empty
        2     6   10     14
       / \   / \  / \   / \
      1   3 5   7 9 11 13 15
```

Joins in the order the recursion returns, from the deepest up:

| join | side | input heights | result height | calls | Step-2 bound |
|---|---|---|---|---:|---:|
| `join_nodes(empty, 6, {7})` | right | 0, 1 | 2 | 1 | `σ=2, h(t_0)=0`: ≤ 3 |
| `join_nodes({1,2,3}, 4, empty)` | left | 2, 0 | 3 | 2 | `σ=3, h(t_0)=0`: ≤ 4 |
| `join_nodes({6,7}, 8, subtree(12))` | right | 2, 3 | 4 | 1 | `σ=4, h(t_1)=2`: ≤ 3 |

```text
  left side (h=3)      found      right side (h=4)
        2                5              8
       / \                           /     \
      1   4                         6       12
         /                           \     /   \
        3                             7   10    14
                                          / \   / \
                                         9  11 13  15
```

That is 4 join calls in total. The right-side heights rise from 0 to 2 to 4 as the joins go up the path. This rising sequence is what makes the costs telescope. A Python copy of `join_nodes` and `split_node` gave the same heights and call counts.

## What `adversary/check.cpp` verifies

Run `./build/adversarial.exe [n ...]` (default 500). Every failure exits with code 1 and names the check that failed.

- **Rotation stress.** After every insert and delete of both families, `audit()` checks key order, heights, subtree counts and balance at every node.
- **Rotation report.** It prints rotations per insert and per delete for both delete orders, and whether the insert count matches `n - bitlen(n)`.
- **Join rejection.** `join` must reject overlapping keys and leave both inputs unchanged. The cases are a left key after the pivot, a right key before it, a pivot equal to an existing key, and a negative pivot ID.
- **Join shapes.** It tests ordered joins at 10 shapes: the taller tree on either side, height gaps of `n` vs 1, `n` vs `n/2`, `n` vs `n/16` and equal sizes, and empty sides. Each joined tree is split at its pivot and rejoined.
- **Split sides.** After every split it checks that the in-order keys of the two halves, with the pivot, exactly equal the original sequence, so every key landed on the correct side.
- **Random splits.** It runs 100 random-pivot splits and 100 random score splits (seed 253), each followed by a rejoin or a side check.

**Measured with `adversarial.exe`.** The insert count equals `n - bitlen(n)` (Theorem 1) at every size tested.
